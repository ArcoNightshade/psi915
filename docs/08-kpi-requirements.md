# KPI requirements of the imported DRM/i915 tree (Gen9)

What the imported Linux DRM core and i915 need from the KPI (`include/`, `src/`), measured on the tree
itself. The data lives in `tools/` (machine-readable, regenerated by `tools/kpi-scan.py`); this document
summarises it and records the Gen9 feature choices. Snapshot: 2026-11-25, drm-kmod 98be24dc9994
(LINUXKPI_VERSION 61400, Linux 6.14 base), include/ as merged from psl/epic-gates-dx5xvk on that date.

## 1. Import (task 1)

`scripts/import-linux.sh` pulls the files from the commit pinned in `third_party/IMPORT_PIN`, after every
upstream file has been classified in `third_party/manifest/{drm,i915}.list`. It applies
`third_party/patches/series`, generates `drm/include/generated/autoconf.h` from
`third_party/config/gen9.config` and writes `third_party/IMPORT_FILES` (blob id, set, licence per file).
`scripts/import-linux.sh -c` checks that the committed trees match pin + manifest + patches + config. That
check passes as of this commit. The patch series is still empty, so drm/ and i915/ are byte-identical to drm-kmod.

| Set | Files | Meaning |
|-----|-------|---------|
| core | 260 | compiled for KBL-R (DRM core, display helpers, TTM, dma-buf, video helpers, i915 core/display/gt/gem/soc) |
| link | 94 | compiled only so the module links: Gen2-8, Gen11+, GuC/HuC/GSC, discrete LMEM/TTM backends, DSI. These are candidates for stub patches |
| hdr / uapi | 524 / 5 | headers (DRM, i915, include/drm/intel, uAPI drm.h, drm_mode.h, drm_fourcc.h, drm_sarea.h, i915_drm.h) |
| extra | 18 | imported but not compiled for Gen9: drm_sched, drm_gpuvm, drm_exec, drm_suballoc, drm_panic, ... |
| aux, kpi-ref | 3, 18 | clear-kernel shader sources; drm-kmod's own linuxkpi/{bsd,gplv2} headers (reference only) |
| optional (not imported) | 97 | debugfs 16, fbdev 10, compat 2, capture 1, perf 2, selftest 52, gen12 11, hwmon 1, lpe 1, auxdev 1 (`-s <set>`) |
| exclude | 42 | FreeBSD glue (drm_os_freebsd.c, intel_freebsd.c, vt_drmfb, *_kmod.c), other drivers' uAPI, build files, amd/radeon |

Facts about drm-kmod that matter for the port (verified in the tree):
- drm-kmod is not pristine Linux. 95 DRM/i915 files carry `__FreeBSD__` conditionals, and some files are
  FreeBSD rewrites. dma-buf.c, dma-fence.c, dma-fence-array.c and dma-fence-chain.c are BSD-2 rewrites
  that use FreeBSD malloc(9), file and sleepqueue APIs. i915_trace.h, intel_uncore_trace.h,
  intel_display_trace.h and drm_trace_freebsd.h are KTR shims. drm_managed.c and intel_acpi.c are
  public-domain rewrites.
- drm-kmod usually writes `#ifdef __linux__ <Linux> #else <FreeBSD> #endif`. illumos defines neither macro,
  so **the FreeBSD branch is the one that compiles** unless a patch changes it. In some places the pattern is
  `#ifdef __linux__ ... #elif defined(__FreeBSD__) ... #endif`, and then nothing is compiled: DRM_DEBUG,
  DRM_DEBUG_KMS, DRM_DEBUG_DRIVER, DRM_ERROR and DRM_DEV_ERROR in drm/include/drm/drm_print.h are
  undefined on illumos. `tools/kpi-bsdisms.tsv` lists the 131 affected files in the Gen9 closure (81 core,
  11 link, 39 headers; 288 `__linux__` and 233 `__FreeBSD__` tests).
- The i915 GEM mmap path is `#ifdef __linux__` code with a FreeBSD alternative. Its functions
  (mmap_offset_attach, insert_mmo, lookup_mmo, vm_open/vm_close, i915_gem_object_mmap) are reported as
  `tree-conditional`, because they are defined only in branches that are false on illumos. The illumos
  devmap/segdev version replaces this path (docs/07), so it is a patch, not a KPI item.
- GuC/HuC stay off below Gen12 (`uc_expand_default_options()` sets enable_guc=0), so on KBL-R the whole
  gt/uc directory is link-only. i915 always creates a TTM device (`intel_region_ttm_device_init()`), but
  integrated parts use the shmem backend, so the GEM TTM backends are link-only while TTM itself is core.
- The uAPI header drm.h selects its kernel branch on `__KERNEL__`, so the illumos module build must define
  `__KERNEL__`. libdrm on illumos uses the "BSDs" branch, which includes `<drm/drm_os_freebsd.h>`. That is a
  userland packaging issue, not handled here.

## 2. Method (task 2)

`tools/kpi-scan.py` scans the 354 compiled Gen9 files (core + link) and the 482 imported headers they
reach. It resolves `#if` blocks that depend only on CONFIG_* (from autoconf.h), `__linux__`, `__FreeBSD__`
(both undefined), `__KERNEL__`, `__x86_64__` and `__cplusplus`. Other conditionals keep every branch. It
records identifiers used but not defined anywhere in the imported tree, and compares them with:
1. include/ (raw headers plus a `gcc -E -dD` pass in the illumos-kernel `check-kmod` configuration against
   tests/stubs/illumos, so the functions that KPI generator macros create are seen);
2. FreeBSD LinuxKPI headers (which give the Linux header name for each item);
3. drm-kmod's kpi-ref headers (drm/linuxkpi);
4. illumos uts sys/ headers.

| Output | Contents |
|--------|----------|
| tools/kpi-requirements.tsv / .json | one row per external symbol: kind (call, tag, macro, type, ident), status, header in include/ / FreeBSD / kpi-ref / illumos, file counts by set (core, link, hdr), call-site count, file list. Sorted by number of core files |
| tools/kpi-headers.tsv | each external `#include <...>`: provided, missing, missing(drmkmod-kpi-ref), freebsd-dummy (FreeBSD satisfies it with an empty header), bsd-native |
| tools/kpi-config-usage.tsv | every CONFIG_* that the closure tests, with its value in autoconf.h |
| tools/kpi-bsdisms.tsv | files with `__linux__`/`__FreeBSD__` conditionals or FreeBSD system includes |
| tools/kpi-unresolved-includes.tsv | quoted includes that resolve to no imported file. Empty, so the import has no missing quoted includes |

Status meanings: `provided` (include/ defines it), `missing` (a LinuxKPI name that include/ lacks),
`illumos-sys` (illumos defines a name of the same spelling, such as errno, memcpy, size_t or PAGE_SIZE;
include/ must expose it with Linux semantics, which it may already do through platform_illumos.h),
`tree-conditional` (needs a patch, see section 1), `tree-generated` (probably produced by token pasting in an
imported macro, such as intel_uncore_read16 or STEP_B0; not a KPI item), `missing-unknown` (none of the
above, see section 4).

**Limits (unverified):** the scan works on text and does not preprocess for real. Expect a few percent false
entries: macro arguments, member names that resemble API names (`vaddr`, `dma` attributed to dma-mapping.h),
and pasted names that the heuristic misses. APIs that appear only inside KPI macro bodies are not seen.
IS_ENABLED and similar macros used in `#if` lines are evaluated rather than counted, so their counts are
lower bounds. A file count counts each header once, not each file that includes it, so i915_drv.h counts as
one file even though about 200 files include it. A real compile against include/ is the only
authoritative missing list. Run the scan again after each KPI merge:
`tools/kpi-scan.py` (needs ~/ref or /home/user/ref with the freebsd and illumos trees, and gcc).

### 3.3 Suggested KPI order (derived from the counts and docs/07's work order)
1. Build basics: linux/kconfig.h + `-include drm/include/generated/autoconf.h`, export.h, module.h,
   moduleparam.h, string_choices.h, string_helpers.h, sizes.h, the errno additions (ETIME, EBADSLT, ...),
   compiler_attributes.h (fallthrough), instruction_pointer.h, seq_file.h, debugfs.h stubs.
2. Device/PCI/IO: device.h, pci.h, io.h, io-mapping.h, ioport.h, dmi.h/mod_devicetable.h, i2c.h,
   interrupt.h/irqreturn.h, pm_runtime.h stubs, capability.h, uaccess.h.
3. Memory/GEM: struct page and mm.h/highmem.h/gfp page APIs, scatterlist.h, dma-mapping.h, shmem_fs.h
   (illumos backing store, R3), ww_mutex.h, iosys-map.h, llist.h, irq_work.h, radix-tree.h, shrinker.h.
4. Sync and fds: dma-fence*.h and dma-resv.h headers (the imported .c files need FreeBSD-to-illumos
   patches), fs.h/file.h/anon_inodes.h, sync_file, sysfs/kobject stubs.

### 3.4 Patches needed (not KPI items)
- drm_print.h: give the illumos build the `__linux__` DRM_DEBUG*/DRM_ERROR definitions.
- `#ifdef __linux__ ... #else` sites in the 81 core files of tools/kpi-bsdisms.tsv. The largest are
  ttm_pool.c, i915_gem_shmem.c, drm_file.c, intel_audio.c, i915_driver.c, intel_gt_pm.c, intel_backlight.c,
  ttm_tt.c and drm_drv.c. Usual fix: change `__linux__` to `(defined(__linux__) || defined(__illumos__))`, or
  add an illumos branch where the illumos code differs (mmap, shmem, fds).
- KTR trace shims (i915_trace.h, intel_uncore_trace.h, intel_display_trace.h, drm_trace_freebsd.h) include
  sys/ktr.h: replace them with empty or SDT versions.
- drm-kmod's dma-buf.c (FreeBSD file and malloc APIs), drm_os_freebsd.h, ttm_sysctl_freebsd.h,
  video/cmdline.c (sys/systm.h): port these, or replace them with psi915 code.
- `missing-unknown` items are mostly FreeBSD-native names in those branches (malloc, M_WAITOK, SYSINIT,
  VM_OBJECT_WLOCK, falloc_noinstall, sx_xunlock) plus real Linux APIs missing from FreeBSD's KPI as well.
  Examples of the latter: blocking_notifier_*, PageWriteback/SetPageReclaim, and ewma_* (generated by
  DECLARE_EWMA, which needs linux/average.h).

## 4. Features to disable or stub for Gen9 (task 3)

The choices are in `third_party/config/gen9.config`, which generates drm/include/generated/autoconf.h.
Symbols that are not listed are not set, as in Linux. `tools/kpi-config-usage.tsv` shows the 95 CONFIG_*
symbols that the closure tests; the 72 that are unset are all debug, selftest or other-platform options,
plus the disabled features below.

| Feature | Choice | Reason |
|---------|--------|--------|
| debugfs (DEBUG_FS) | off | no debugfs on illumos; headers still need stubs (section 3.2) |
| GVT-g, KVMGT | off | no hypervisor integration |
| perf/PMU, OA (PERF_EVENTS) | off | i915_perf.c, i915_pmu.c not imported |
| selftests, kunit, DRM_DEBUG_* | off | |
| Gen12-only: PXP, DP tunnel, HDCP-over-GSC, MEI | off | not on KBL-R; files in the gen12 set |
| error capture (CAPTURE_ERROR) | off for bring-up | hang reset does not need it; enable once sysfs bin attributes exist |
| fbdev emulation, DRM_CLIENT, DRM_PANIC | off | illumos console (tem/vgatext) handoff is psi915 glue (docs/06 R5) |
| COMPAT (32-bit ioctls) | off | ddi_model_convert_from handles 32-bit ioctls per ioctl |
| MMU_NOTIFIER (userptr) | off | userptr returns -ENODEV; iris works without it |
| BACKLIGHT_CLASS_DEVICE, ACPI_VIDEO | off | brightness through opregion/PWM first; class device later |
| VGA_ARB, VGA_SWITCHEROO, AGP, INTEL_GTT, MTRR, SWIOTLB, INTEL_IOMMU | off | not applicable on illumos amd64 Gen9 |
| PM, PM_SLEEP, SUSPEND | on | code paths stay compiled; the KPI maps them to DDI_SUSPEND/RESUME; runtime PM may be stubbed |
| ACPI, DMI, X86_PAT, AS_MOVNTDQA | on | opregion, quirks, WC mappings, i915_memcpy |
| i915 timeouts (heartbeat, preempt, ...) | Linux defaults | taken from drm-kmod kconfig.mk |

Link-closure stubbing (later patches, unverified effort): the 94 `link` files can be compiled out once
stubs replace their entry points. The largest gains are gt/uc (GuC/HuC/GSC, 18 files), discrete
LMEM/TTM backends and the DSI/DVO/SDVO/TV encoders. That shrinks the KPI surface (e.g. mipi_dsi, pwm,
platform_device users) but costs a patch to carry.

## 5. Not verified
- No file in drm/ or i915/ has been compiled against include/. The missing list is a static estimate.
- Licence detection in IMPORT_FILES is heuristic (third_party/LICENSES/README.md); GPL-only files need an
  owner decision.
- The set assignments (core/link) come from reading the code and drm-kmod's Makefiles, not from a linker
  run. Some link files may turn out unnecessary, and some excluded or optional files may turn out
  necessary (e.g. if a debugfs symbol is referenced without a stub).
- The exact Linux commit behind drm-kmod's 6.14 base is not recorded.
- CONFIG choices marked "(unverified)" in gen9.config, and the effect of CONFIG_INTEL_IOMMU off on VT-d
  quirks, have not been checked.
