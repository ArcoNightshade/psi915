# KPI requirements of the imported DRM/i915 tree (Gen9)

This document covers three things for the imported upstream Linux DRM core and i915:
- what they need from the KPI (`include/`, `src/`), measured on the imported tree itself;
- the Gen9 feature choices;
- the boundary of the separate GPL-2.0 module and psi915's BSD replacements (drm_bsd/).

The data is in `tools/`, which is machine-readable and regenerated by `tools/kpi-scan.py`.

Snapshot taken 2026-11-26:
- upstream Linux tag v6.14 (commit 38fec10eb60d, tag object 35ff3b0f4596; owner decision, docs/06);
- include/ as merged from psl/epic-gates-dx5xvk that day.

drm-kmod and OpenBSD are reference trees only.

## 1. Import (task 1)

How `scripts/import-linux.sh` works:
- It clones the pinned tag shallow and blobless (`$REF/linux`).
- It classifies every file under the manifest scopes (drivers/gpu/drm, drivers/dma-buf, drivers/video,
  include/drm, include/uapi/drm, plus drivers/platform/x86/intel_ips.h) through `third_party/manifest/{drm,i915,gpl}.list`.
- It extracts the selected files with `git archive` and refuses GPL-only files outside gpl/.
- It applies `third_party/patches/series` and generates `drm/include/generated/autoconf.h` from
  `third_party/config/gen9.config`.
- It writes `third_party/IMPORT_FILES` (blob, set, licence per file).

`-c` verifies the committed trees against pin + manifest + patches + config, then runs the five GPL-boundary
checks (section 5). Both pass as of this commit. Five patches are applied (section 3.4); every other
imported file is byte-identical to v6.14.

The i915 sets come from the upstream i915 Makefile:
- `i915-y` and `CONFIG_X86`/`CONFIG_ACPI` objects are core or link.
- Every other `i915-$(CONFIG_*)` object goes to the optional set named after that option.

DRM core sets were chosen per file from the drm Makefiles and from the symbols i915 actually uses.

| Set | Files (drm / i915 / gpl) | Meaning |
|-----|--------------------------|---------|
| core | 69 / 184 / 8 | compiled for KBL-R (plus 7 drm_bsd/ files, section 5) |
| link | 2 / 100 / 0 | compiled only so the module links: Gen2-8, Gen11+, GuC/HuC/GSC, PXP base (unconditional upstream), discrete LMEM/TTM, DSI. Candidates for stub patches |
| hdr, uapi | 108+5 / 395 / 32 | headers; uAPI: drm.h, drm_mode.h, drm_fourcc.h, drm_sarea.h, i915_drm.h |
| extra | 14 / 0 / 5 | imported, not compiled for Gen9: drm_sched, drm_gpuvm, drm_exec, drm_suballoc, drm_panic, unused KMS helpers |
| aux | 0 / 3 / 0 | clear-kernel shader sources |
| optional (not imported) | 202 | selftest 106, gvt 42, replaced 19 (GPL originals superseded by drm_bsd/), fbdev 10, gen12 8, debugfs 7, kunit 3, compat 2, capture, perf (PMU), hwmon, edidfw, auxdev, cec |
| exclude | 134 entries | other DRM drivers and helpers, dma-buf heaps/udmabuf/sw_sync, fbdev/backlight/console, build files |

Facts that matter for the port (verified in the tree):
- **GuC/HuC.** `uc_expand_default_options()` sets enable_guc=0 below Gen12, so gt/uc is link-only on KBL-R.
- **TTM.** i915 always creates a TTM device (`intel_region_ttm_device_init()`), so TTM is core. Integrated
  parts use the shmem backend, so the GEM TTM backends are link-only.
- **Unconditional objects that do not fit illumos.** Upstream builds these unconditionally:
  - `i915_perf.c` (OA streams): kept core.
  - The PXP base files: link.
  - `gem/i915_gemfs.c`: core, but it mounts a Linux tmpfs. Patch 0001 makes it a no-op.
- **Cross-tree include.** `gt/intel_rps.c` includes `../../../platform/x86/intel_ips.h`, a GPL header in gpl/.
  Patch 0002 compiles the include and the Ironlake intel_ips handshake out.
- **Defines the build must pass.** The uAPI header drm.h picks its kernel branch on `__KERNEL__`, so the
  illumos module build defines `__KERNEL__`. It also needs `-include` of `linux/kconfig.h` and of the generated
  autoconf.h, as Kbuild does.
- **Tracepoints.** The upstream drm_trace.h, i915_trace.h, intel_display_trace.h and intel_uncore_trace.h
  are GPL-2.0. drm_bsd/ replaces them with no-op headers that define every `trace_*()` the MIT code calls,
  generated by tools/gen-drm-bsd-trace.py. The KPI still needs `<trace/events/dma_fence.h>` for
  intel_breadcrumbs.c and G1.

## 2. Method (task 2)

`tools/kpi-scan.py` scans the 370 compiled Gen9 files (core + link, including drm_bsd/) and the 498 headers
they reach. 17 of these files are in gpl/. It resolves `#if` on CONFIG_* (autoconf.h), `__KERNEL__`, `__x86_64__` and `__cplusplus`
and keeps both branches for anything else. It records identifiers that the scanned files use but no imported
file defines, and compares each with four references:
1. include/, read raw and through `gcc -E -dD` in the `check-kmod` illumos-kernel configuration. The
   expansion reveals functions generated by KPI macros. Names that are visible only through the stub illumos
   headers count as provided and show as `illumos:sys/...`.
2. Upstream Linux v6.14 headers, extracted on demand with `import-linux.sh -R` into `$REF/linux-hdrs`. These
   give the Linux header name and that header's SPDX licence.
3. The FreeBSD LinuxKPI headers (a BSD implementation reference).
4. illumos uts sys/ headers.

| Output | Contents |
|--------|----------|
| tools/kpi-requirements.tsv / .json | One row per external symbol. Columns: kind, status, header in include/, Linux header with licence, FreeBSD header, illumos header, counts of core/link/header/gpl files, call sites, file list. Sorted by core-file count |
| tools/kpi-headers.tsv | Each external `#include <...>`: provided, missing or freebsd-dummy, plus the upstream header's licence |
| tools/kpi-config-usage.tsv | Every CONFIG_* that the closure tests, with its value |
| tools/kpi-unresolved-includes.tsv | Quoted includes that resolve to nothing. Empty: the import is include-closed |
| tools/gpl-boundary.tsv, tools/gpl-headers.tsv | The GPL module boundary (section 5) |

Status values:

| Status | Meaning |
|--------|---------|
| provided | include/ supplies the name |
| missing | a Linux or FreeBSD LinuxKPI header defines it; include/ does not |
| illumos-sys | only illumos defines it |
| tree-conditional | defined in the tree only under CONFIG options that are off. Five such names, e.g. DRM_DP_MST_TOPOLOGY_REF_GET under CONFIG_DRM_DEBUG_DP_MST_TOPOLOGY_REFS. They show configuration seams, not KPI items |
| tree-generated | produced by token pasting in imported macros (intel_uncore_read16, STEP_B0, ...). Not KPI items |
| missing-unknown | none of the above |

**Limits (unverified):** the scan works on text and does not run a real preprocessor. Expect a few percent
false entries:
- members or locals whose names match an API name: `inode` and `dma` used as identifiers, `reason`, `event`;
- names produced inside TRACE_EVENT or DECLARE_EWMA (`ewma_*`) bodies, which are reported as missing-unknown.

Other gaps and caveats:
- APIs used only inside KPI macro bodies are invisible to the scan.
- IS_ENABLED and similar macros in `#if` lines are evaluated, not counted, so their counts are lower bounds.
- A header counts as one file however many files include it.

A real compile against include/ is the only authoritative list. Run the scanner again after each KPI merge.

### 4.1 Review against the v6.14 i915 Kconfig (2026-11-26)

Method: I compared gen9.config with the `select`/`depends on` rules of drivers/gpu/drm/i915/Kconfig
(DRM_I915 and its sub-options) and with every CONFIG_* test in the Gen9 closure
(tools/kpi-config-usage.tsv). For each unset symbol the code tests, I read the code and judged what
happens at runtime on KBL-R. The judgements come from reading code; nothing has run on hardware.

The `depends on` rules all hold: X86 && PCI, !PREEMPT_RT, and DRM_I915_DP_TUNNEL off because it needs USB4.
Where gen9.config leaves a symbol off that DRM_I915 `select`s, the choices are deliberate:

| Kconfig select | gen9.config | Runtime effect on Gen9.5 | Verdict |
|----------------|-------------|--------------------------|---------|
| INTEL_GTT if X86 | off | intel_ggtt_gmch.c (Gen2-5 GGTT) has no intel-gtt driver; patch 0004 makes probing those devices fail with -ENODEV. Gen6+ GGTT never uses it | OK |
| BACKLIGHT_CLASS_DEVICE, ACPI_VIDEO, ACPI_WMI, INPUT, X86_PLATFORM_DEVICES if ACPI | off | No backlight device is registered, so userspace cannot set eDP brightness. | IOSF_MBI if X86 | off | IOSF sideband only on VLV/CHV (link-only vlv_sideband.c) | OK |
| SND_HDA_I915 if SND_HDA_CORE, AUXILIARY_BUS | off | No HDMI/DP audio binding (component framework). Video is unaffected | OK (audio is out of scope) |

| DRM_CLIENT_SELECTION, FB_IOMEM_HELPERS | off | No in-kernel fbdev client; the illumos console handoff is separate (docs/06 R5) | OK |

Other unset symbols the closure tests, and their effect:

| Symbol (upstream default) | Effect | Verdict |
|---------------------------|--------|---------|
| DRM_I915_CAPTURE_ERROR (y) | No GPU error state after a hang. Hang detection and reset (heartbeat, engine/GT reset) work without it | OK for bring-up; enable once an error-state export path exists |
| MMU_NOTIFIER (selected by DRM_I915_USERPTR, default y) | I915_GEM_USERPTR fails with -ENODEV. iris works without it; some anv paths would lose host-pointer import | OK (docs/07) |

| FRAMEBUFFER_CONSOLE | The BIOS framebuffer is kept even when it is larger than half of stolen memory, which suits the console takeover | OK |
| PREEMPT_COUNT | Only disables a debug assertion in _wait_for_atomic, as on non-preemptible Linux | OK |
| COMPAT | drmglue refuses 32-bit ioctl callers (docs/09); 64-bit Xorg/Mesa required | OK, known |
| PROC_FS, DEBUG_FS, PERF_EVENTS, HWMON, OF, PXP, GVT, MEI_* | Features off; the headers' stubs take over | OK |

Two findings that the configuration does not cover:
1. **VT-d workarounds depend on the KPI, not on CONFIG.** i915 decides through `i915_vtd_active()`
   (`device_iommu_mapped()`, which is constant false in the KPI). On Gen9, `intel_scanout_needs_vtd_wa()`
   then skips the 256 KiB scanout alignment and the guard pages that the display engine needs when the
   IOMMU translates its fetches. If the illumos immu ever maps the GPU, KBL-R would see DMA faults and
   display corruption. CONFIG_INTEL_IOMMU and IOMMU_API are tested nowhere in the closure, so their
   "not set" lines have no effect. Request to the KPI: docs/11 R-K7. Until then, the GPU must not sit
   behind an active immu (unverified on the target).
2. **CONFIG_AS_MOVNTDQA=y is inert.** i915_memcpy.c compiles the SSE4.1 path, but the KPI hides SSE4.1
   (docs/04), so `i915_memcpy_from_wc()` always reports failure and callers use the slow copy. That is
   correct but slow when reading back from WC memory. No change.

No CONFIG value needed changing. gen9.config now carries a comment block that records these deliberate
divergences.

Link-closure stubbing (later patches, effort unverified): stubbing out the entry points of the 100 i915
`link` files would let them be dropped. The largest groups are gt/uc (GuC/HuC/GSC), the discrete LMEM/TTM
backends, the DSI/DVO/SDVO/TV encoders and Gen11+ PHYs. Dropping them removes KPI needs such as mipi_dsi,
pwm and platform_device users, at the cost of carrying patches.

## 5. GPL-2.0 module boundary and drm_bsd/

Owner decision (docs/06): GPL-only code ships as separate GPL-2.0 module(s) built from gpl/. drm/ and i915/
contain only MIT, HPND or dual-licensed code. The owner then accepted the recommendation to break the module
cycle by replacing the coupled GPL files with BSD clean-room code (option (b), plus stubs (c)).

### 5.1 drm_bsd/: BSD-2-Clause replacements (drm_bsd/MANIFEST)

The replacements were written from documented API behaviour, the MIT/BSD callers and headers in drm/ and
i915/, and the MIT uAPI. They were not written from the GPL sources. Those sources are not imported any more:
they sit in set `replaced`, importable only for reference with `-s replaced`. drm_bsd/ is compiled into the
same modules as the files it serves: DRM core and video into drm, intel_acpi.c into i915. Its include
directories come first on the include path.

| drm_bsd file | Replaces | Behaviour on psi915 |
|--------------|----------|---------------------|
| drm_managed.c/.h | drm_managed.c/.h | full drmm_* interface; resources are released newest first at device release |
| drm_sysfs.c/.h | drm_sysfs.c/.h | struct device per minor (card%d/renderD%d/accel%d) and per connector. Hotplug, property and lease events go to an optional hook (`drm_bsd_set_uevent_hook`) for an illumos sysevent. No sysfs attributes |
| drm_lease.c/.h | drm_lease.c/.h | no leases are granted: CREATE_LEASE returns EOPNOTSUPP and REVOKE returns ENOENT. LIST_LESSEES returns 0. GET_LEASE returns every lease-required object for an owner. lease_held is always true |
| drm_gem_atomic_helper.c/.h | drm_gem_atomic_helper.c/.h (GPL-2.0-or-later) | drm_gem_plane_helper_prepare_fb only. It waits for the write fences of the fb objects plus any explicit fence. Replaced so that the GPL drm_format_helper.h is no longer pulled in (docs/04 R-G1) |
| drm_writeback.c/.h | drm_writeback.c/.h | stub: i915 has no writeback connectors. Job lifetime functions only; no connector init |
| i915 display/intel_acpi.c | intel_acpi.c | no-ops (vga_switcheroo DSM, BIOS-data DSM, DIDL, ACPI fwnodes, acpi_video) |
| video/cmdline.c | cmdline.c | per-output options set by the glue (`video_bsd_set_option`) instead of `video=` |
| video/nomodeset.c | nomodeset.c | policy set by the glue (`video_bsd_set_firmware_drivers_only`); default off |
| drm_trace.h, i915_trace.h, intel_display_trace.h, intel_uncore_trace.h | upstream trace headers | no-op trace points (tools/gen-drm-bsd-trace.py) |
| (none) | drm_trace_points.c, i915_trace_points.c, intel_display_trace.c, intel_uncore_trace.c | define nothing with CONFIG_TRACEPOINTS off |

The no-op functions are reductions of upstream behaviour. Each source file states what it omits. None of
the omitted behaviour is needed for KBL-R bring-up (unverified until the hardware runs).

### 5.3 Checks (`scripts/import-linux.sh -c`, policy in third_party/gpl-policy.conf)
1. No GPL-only file outside gpl/, and every drm_bsd/ source carries `SPDX-License-Identifier: BSD-2-Clause`.
2. The compiled GPL files are exactly the G1/G2 allow-list.
3. No MIT/BSD file (drm/, i915/ outside set extra, drm_bsd/) includes a GPL header from gpl/, except the
   listed debts. Includes inside `#ifndef CONFIG_PSI915` are skipped.
4. G1 includes no `<drm/...>` header and no quoted header outside its own directory.
5. No drm/ file (and no drm_bsd DRM-core file) uses a G2 export. Comments are ignored.

### 5.4 Remaining debts and open points
1. **GPL headers still included by MIT code** (`allow-header` in gpl-policy.conf; tools/gpl-headers.tsv):
   - drm_mipi_dsi.h: link-only DSI encoders and drm_mipi_dsi.c.
   - i915_hdcp_interface.h: HDCP 2.2 over MEI.
   - drm_accel.h (drm_drv.c), drm_of.h, drm_dp_mst_topology_internal.h.
   Each needs a BSD header in drm_bsd/ or a patch. Most of them disappear when the link-only files are
   stubbed.
2. **dma-fence ABI.** G1 compiles against the KPI's BSD dma-fence/dma-resv/dma-buf/sync_file headers, which
   must match the upstream structure layouts (docs/10 R10). The v6.14 headers serve as the specification
   only; their text is never copied.
3. **drm_device.h and drm_gem_framebuffer_helper.h** carry no licence notice (third_party/LICENSES).
4. **Legal question.** Can a CDDL kernel load GPL-2.0 modules that exchange symbols with MIT/BSD modules?
   Still open (docs/06). Not verified.
5. **Not compiled yet.** The drm_bsd/ sources and the patches have only been checked for syntax in pieces:
   the trace headers and drm_managed.h against include/ in userland mode. A real build against the KPI is
   pending.

## 6. Not verified
- Nothing in drm/, i915/, gpl/ or drm_bsd/ has been compiled against include/. The missing list is a static
  estimate, and the patches are untested.
- The core/link assignments come from the Makefiles and from reading the code, not from a linker run. The
  boundary symbol counts come from the scanner's definition heuristics and contain some noise.
- The licence detection in IMPORT_FILES is not reviewed by hand. The licences of headers with no notice need
  an owner decision.
- The effect of CONFIG_INTEL_IOMMU being off on VT-d quirks is unchecked, as are the choices marked
  "(unverified)" in gen9.config.
- Whether the GPL module split is legally workable on illumos.
