# KPI requirements of the imported DRM/i915 tree (Gen9)

This document covers three things for the imported upstream Linux DRM core and i915:
- what they need from the KPI (`include/`, `src/`), measured on the imported tree itself;
- the Gen9 feature choices;
- the boundary of the separate GPL-2.0 module.

The data is in `tools/`, which is machine-readable and regenerated by `tools/kpi-scan.py`.

Snapshot taken 2026-11-26:
- upstream Linux tag v6.14 (commit 38fec10eb60d, tag object 35ff3b0f4596; owner decision, docs/06);
- include/ as merged from psl/epic-gates-dx5xvk that day.

drm-kmod and OpenBSD are reference trees only.

## 1. Import (task 1)

How `scripts/import-linux.sh` works:
- It clones the pinned tag shallow and blobless (`$REF/linux`).
- It classifies every file under the manifest scopes (drivers/gpu/drm, drivers/dma-buf, drivers/video,
  include/drm, include/uapi/drm, plus drivers/platform/x86/intel_ips.h) through `third_party/manifest/{drm,i915,gpl}.list`.
- It extracts the selected files with `git archive` and refuses GPL-only files outside gpl/.
- It applies `third_party/patches/series` and generates `drm/include/generated/autoconf.h` from
  `third_party/config/gen9.config`.
- It writes `third_party/IMPORT_FILES` (blob, set, licence per file).

`-c` verifies the committed trees against pin + manifest + patches + config and passes as of this commit. The
series is empty, so every imported file is byte-identical to v6.14.

The i915 sets come from the upstream i915 Makefile:
- `i915-y` and `CONFIG_X86`/`CONFIG_ACPI` objects are core or link.
- Every other `i915-$(CONFIG_*)` object goes to the optional set named after that option.

DRM core sets were chosen per file from the drm Makefiles and from the symbols i915 actually uses.

| Set | Files (drm / i915 / gpl) | Meaning |
|-----|--------------------------|---------|
| core | 69 / 184 / 19 | compiled for KBL-R |
| link | 2 / 100 / 0 | compiled only so the module links: Gen2-8, Gen11+, GuC/HuC/GSC, PXP base (unconditional upstream), discrete LMEM/TTM, DSI. Candidates for stub patches |
| hdr, uapi | 108+5 / 395 / 40 | headers; uAPI: drm.h, drm_mode.h, drm_fourcc.h, drm_sarea.h, i915_drm.h |
| extra | 14 / 0 / 5 | imported, not compiled for Gen9: drm_sched, drm_gpuvm, drm_exec, drm_suballoc, drm_panic, unused KMS helpers |
| aux | 0 / 3 / 0 | clear-kernel shader sources |
| optional (not imported) | 183 | selftest 106, gvt 42, fbdev 10, gen12 8, debugfs 7, kunit 3, compat 2, capture, perf (PMU), hwmon, edidfw, auxdev, cec |
| exclude | 134 entries | other DRM drivers and helpers, dma-buf heaps/udmabuf/sw_sync, fbdev/backlight/console, build files |

Facts that matter for the port (verified in the tree):
- **GuC/HuC.** `uc_expand_default_options()` sets enable_guc=0 below Gen12, so gt/uc is link-only on KBL-R.
- **TTM.** i915 always creates a TTM device (`intel_region_ttm_device_init()`), so TTM is core. Integrated
  parts use the shmem backend, so the GEM TTM backends are link-only.
- **Unconditional objects that do not fit illumos.** Upstream builds these unconditionally:
  - `i915_perf.c` (OA streams): kept core.
  - The PXP base files: link.
  - `gem/i915_gemfs.c`: core, but it mounts a Linux tmpfs, so illumos needs a patch or a replacement.
- **Cross-tree include.** `gt/intel_rps.c` includes `../../../platform/x86/intel_ips.h`, which now lives in
  gpl/. The build needs an include-path arrangement or a patch.
- **Defines the build must pass.** The uAPI header drm.h picks its kernel branch on `__KERNEL__`, so the
  illumos module build defines `__KERNEL__`. It also needs `-include` of `linux/kconfig.h` and of the generated
  autoconf.h, as Kbuild does.
- **Tracepoints.** drm_trace.h, i915_trace.h, intel_display_trace.h and intel_uncore_trace.h use TRACE_EVENT.
  With CONFIG_TRACEPOINTS off, `linux/tracepoint.h` must turn them into no-op `trace_*()` inlines. The
  scanner reports `trace_i915_*` names as missing-unknown because they come from TRACE_EVENT expansion.

## 2. Method (task 2)

`tools/kpi-scan.py` scans the 374 compiled Gen9 files (core + link) and the 499 imported headers they reach,
37 of them in gpl/. It resolves `#if` on CONFIG_* (autoconf.h), `__KERNEL__`, `__x86_64__` and `__cplusplus`
and keeps both branches for anything else. It records identifiers that the scanned files use but no imported
file defines, and compares each with four references:
1. include/, read raw and through `gcc -E -dD` in the `check-kmod` illumos-kernel configuration. The
   expansion reveals functions generated by KPI macros. Names that are visible only through the stub illumos
   headers count as provided and show as `illumos:sys/...`.
2. Upstream Linux v6.14 headers, extracted on demand with `import-linux.sh -R` into `$REF/linux-hdrs`. These
   give the Linux header name and that header's SPDX licence.
3. The FreeBSD LinuxKPI headers (a BSD implementation reference).
4. illumos uts sys/ headers.

| Output | Contents |
|--------|----------|
| tools/kpi-requirements.tsv / .json | One row per external symbol. Columns: kind, status, header in include/, Linux header with licence, FreeBSD header, illumos header, counts of core/link/header/gpl files, call sites, file list. Sorted by core-file count |
| tools/kpi-headers.tsv | Each external `#include <...>`: provided, missing or freebsd-dummy, plus the upstream header's licence |
| tools/kpi-config-usage.tsv | Every CONFIG_* that the closure tests, with its value |
| tools/kpi-unresolved-includes.tsv | Quoted includes that resolve to nothing. Empty: the import is include-closed |
| tools/gpl-boundary.tsv, tools/gpl-headers.tsv | The GPL module boundary (section 5) |

Status values:

| Status | Meaning |
|--------|---------|
| provided | include/ supplies the name |
| missing | a Linux or FreeBSD LinuxKPI header defines it; include/ does not |
| illumos-sys | only illumos defines it |
| tree-conditional | defined in the tree only under CONFIG options that are off. Five such names, e.g. DRM_DP_MST_TOPOLOGY_REF_GET under CONFIG_DRM_DEBUG_DP_MST_TOPOLOGY_REFS. They show configuration seams, not KPI items |
| tree-generated | produced by token pasting in imported macros (intel_uncore_read16, STEP_B0, ...). Not KPI items |
| missing-unknown | none of the above |

**Limits (unverified):** the scan works on text and does not run a real preprocessor. Expect a few percent
false entries:
- members or locals whose names match an API name: `inode` and `dma` used as identifiers, `reason`, `event`;
- names produced inside TRACE_EVENT or DECLARE_EWMA (`ewma_*`) bodies, which are reported as missing-unknown.

Other gaps and caveats:
- APIs used only inside KPI macro bodies are invisible to the scan.
- IS_ENABLED and similar macros in `#if` lines are evaluated, not counted, so their counts are lower bounds.
- A header counts as one file however many files include it.

A real compile against include/ is the only authoritative list. Run the scanner again after each KPI merge.

### 3.3 Suggested KPI order
1. **Build basics:** kconfig.h, export.h, module.h/moduleparam.h, string_choices.h, string_helpers.h,
   sizes.h, sprintf.h, compiler_attributes.h, the errno additions (asm-generic/errno.h: EPROTO, ENOBUFS, ...),
   seq_file.h, debugfs.h stubs, tracepoint.h no-ops.
2. **Device and IO remainder:** i2c.h, dmi.h/mod_devicetable.h, acpi glue, capability.h, notifier.h,
   firmware.h (request_firmware for DMC), component.h (audio).
3. **Memory/GEM:** mm.h/mm_types.h VMA API on devmap, shmem_fs.h (illumos backing store), pagemap/pagevec,
   llist.h, radix-tree.h, shrinker.h, iosys-map.h.
4. **Sync and fds:** BSD dma-fence*.h, dma-resv.h, dma-buf.h and sync_file.h, compatible with the gpl/
   implementations; fs.h/file.h/anon_inodes.h/poll.h.

### 3.4 Patches expected (not KPI items)
- `gem/i915_gemfs.c` and the shmem object backend: replace with an illumos backing store.
- The GEM mmap fault path (`i915_gem_mman.c`): devmap/segdev glue (docs/07).
- `gt/intel_rps.c`: the intel_ips.h cross-tree include.
- Optional stub patches for link-only files, to shrink the KPI surface (section 4).

## 4. Features to disable or stub for Gen9 (task 3)

The choices live in `third_party/config/gen9.config`, which generates drm/include/generated/autoconf.h.
CONFIG symbols not listed there are unset, as in Linux. tools/kpi-config-usage.tsv lists the CONFIG_* symbols
the closure tests; the unset ones are debug, selftest and other-platform options plus the disabled features
below.

| Feature | Choice | Reason |
|---------|--------|--------|
| debugfs (DEBUG_FS) | off | no debugfs on illumos; headers still need stubs |
| GVT-g, KVMGT | off | no hypervisor integration |
| perf PMU (PERF_EVENTS) | off | i915_pmu.c not imported; i915_perf.c (OA) stays, as upstream builds it unconditionally |
| selftests, KUnit, DRM/i915 debug options | off | |
| Gen12-only: PXP, DP tunnel, MEI/GSC HDCP | off | PXP base files are link-only (unconditional upstream) |
| error capture (CAPTURE_ERROR) | off for bring-up | hang reset does not need it |
| fbdev emulation, DRM_CLIENT/CLIENT_LIB, DRM_PANIC | off | illumos console (tem/vgatext) handoff is psi915 glue (docs/06 R5) |
| COMPAT (32-bit ioctls) | off | illumos uses ddi_model_convert_from per ioctl |
| MMU_NOTIFIER (userptr) | off | userptr returns -ENODEV; iris works without it |
| BACKLIGHT_CLASS_DEVICE, ACPI_VIDEO | off | opregion/PWM brightness first |
| VGA_ARB, VGA_SWITCHEROO, AGP, INTEL_GTT, MTRR, SWIOTLB, INTEL_IOMMU, OF | off | not applicable on illumos amd64 Gen9 |
| DMA_SHARED_BUFFER, SYNC_FILE | on | dma-buf and sync_file fds (gpl/ module) |
| dma-buf heaps, udmabuf, sw_sync, sysfs stats | off | not needed by i915 |
| PM, PM_SLEEP, SUSPEND | on | mapped to DDI_SUSPEND/RESUME; runtime PM may be stubbed |
| ACPI, DMI, X86_PAT, AS_MOVNTDQA | on | opregion, quirks, WC mappings, i915_memcpy |
| TRACEPOINTS | off | trace headers become no-ops |
| i915 timeouts (heartbeat, preempt, ...) | upstream Kconfig.profile defaults | checked against v6.14 |

Link-closure stubbing (later patches, effort unverified): stubbing out the entry points of the 100 i915
`link` files would let them be dropped. The largest groups are gt/uc (GuC/HuC/GSC), the discrete LMEM/TTM
backends, the DSI/DVO/SDVO/TV encoders and Gen11+ PHYs. Dropping them removes KPI needs such as mipi_dsi,
pwm and platform_device users, at the cost of carrying patches.

## 5. GPL-2.0 module boundary

The owner decided (docs/06) that every GPL-only file in the Gen9 set ships as a separate GPL-2.0 module built
from gpl/. drm/ and i915/ hold only MIT, HPND or dual-licensed code. The import script enforces this. The
full file list is in third_party/LICENSES/README.md.

Contents of gpl/ (19 compiled files):

| Group | Files | Upstream EXPORT_SYMBOLs |
|-------|-------|-------------------------|
| dma-buf | dma-buf.c, dma-fence.c, dma-fence-array.c, dma-fence-chain.c, dma-fence-unwrap.c, sync_file.c | 58 |
| DRM core pieces | drm_managed.c (7), drm_sysfs.c (5), drm_writeback.c (7), drm_gem_framebuffer_helper.c (12), drm_lease.c (0), display/drm_hdcp_helper.c (3), drm_trace_points.c | 34 |
| i915 | display/intel_acpi.c, intel_display_trace.c, i915_trace_points.c, intel_uncore_trace.c | 0 |
| video | cmdline.c (2), nomodeset.c (1) | 3 |

Symbols that cross the boundary (tools/gpl-boundary.tsv; Gen9 closure, scanner heuristics):

| Direction | Function/variable symbols | Header-level names | Examples |
|-----------|---------------------------|--------------------|----------|
| gpl -> drm/i915 | 50 | 92 | dma_fence_init/signal/add_callback/wait_timeout, dma_buf_attach/map_attachment/put, sync_file_create/get_fence, drm_lease_held/filter_crtcs and the lease ioctls, drm_sysfs_hotplug_event/connector_*_event, drm_writeback_prepare_job/cleanup_job/set_fb, drmm_kstrdup, video_get_options, video_firmware_drivers_only |
| drm/i915 -> gpl | about 63 | about 182 | drm_connector_init/cleanup, drm_encoder_init, drm_framebuffer_init, drm_property_create*, drm_mode_object_find, drm_master_get/put, drm_gem_object_lookup/handle_create, dma_resv_wait_timeout, drm_ioctl/drm_read/drm_poll (named in the DRM_ACCEL_FOPS macro of drm_accel.h, unused with CONFIG_DRM_ACCEL off), dma_resv_init/fini (dma-buf.c), plus i915 request/vma/crtc functions named in the i915 trace headers |

Header-level names come from macros, inlines and types. They are compiled into the user and are not link
symbols. Two examples of what this means at link time:
- MIT code calls `drmm_add_action_or_reset()` and `drmm_kzalloc()`, which drm_managed.h defines. What crosses
  the boundary are `__drmm_add_action_or_reset` and `drmm_kmalloc` in the GPL module.
- The trace headers make i915 functions appear as boundary users. With CONFIG_TRACEPOINTS off, those
  references disappear.

Consequences and open points:
1. **Dependency cycle.** Upstream these files live inside drm.ko and i915.ko and call each other without
   exports: drm_lease.c (733 lines), drm_sysfs.c (582) and intel_acpi.c (360) have unexported entry points used by drm_drv.c,
   drm_ioctl.c and i915 display. Splitting them out creates calls in both directions. illumos module
   dependencies (`-N`) cannot be circular, so the cycle must be broken. Options, cheapest first:
   - (a) Make the GPL module depend on drm/i915 and reach the reverse edges (drm_managed, drm_sysfs, drm_lease,
     intel_acpi, trace points) through a registration table of function pointers that the MIT side fills at
     load time.
   - (b) Replace the small, tightly coupled files (drm_managed.c, 312 lines; drm_sysfs.c, drm_lease.c,
     intel_acpi.c, cmdline.c, nomodeset.c, the trace-point .c files) with BSD clean-room versions in psi915
     code. The GPL module then shrinks to dma-buf/dma-fence/sync_file, drm_writeback, drm_hdcp_helper and
     drm_gem_framebuffer_helper, which depend only on the KPI and DRM core, so dependencies run one way:
     gpl -> drm.
   - (c) Disable the features through patches. drm_writeback is only needed for link closure, because i915
     has no writeback connectors, and drm_lease could become a stub ioctl returning -EOPNOTSUPP.
   Recommendation (unverified effort): (b) plus (c), leaving a one-way GPL module for dma-buf/fence.
2. **GPL headers in MIT code.** These are listed in tools/gpl-headers.tsv and third_party/LICENSES/README.md
   (question 1): drm_managed.h, drm_mipi_dsi.h, drm_writeback.h, i915_hdcp_interface.h, intel-gtt.h and the
   trace headers. Option (b) also removes most of them.
3. **dma-fence ABI.** The GPL dma-fence/dma-buf implementations compile against the KPI's BSD headers, and the
   MIT side uses the same headers. struct layouts and inline semantics must match upstream exactly; the
   v6.14 headers serve as the specification only, and their text is never copied.
4. **Legal question.** Can a CDDL kernel load a GPL-2.0 module that exchanges symbols with MIT and BSD
   modules? This is still open (docs/06). Not verified.

## 6. Not verified
- Nothing in drm/, i915/ or gpl/ has been compiled against include/. The missing list is a static estimate.
- The core/link assignments come from the Makefiles and from reading the code, not from a linker run. The
  boundary symbol counts come from the scanner's definition heuristics and contain some noise.
- The licence detection in IMPORT_FILES is not reviewed by hand. The licences of headers with no notice need
  an owner decision.
- The effect of CONFIG_INTEL_IOMMU being off on VT-d quirks is unchecked, as are the choices marked
  "(unverified)" in gen9.config.
- Whether the GPL module split is legally workable on illumos.
